isoboard is built in the open, and what comes next is shaped by the people who use it. Feature requests and bug reports go to [GitHub Issues](https://github.com/carlesonielfa/isoboard-app/issues) on the isoboard repository, where anyone can read them, add details and vote.

## How do I request a feature?

1. [Search the open issues](https://github.com/carlesonielfa/isoboard-app/issues?q=is%3Aissue%20is%3Aopen%20label%3Aenhancement) to see whether someone already asked for it.
2. If it exists, add a 👍 reaction to the first post. Add a comment if your use case is different.
3. If it does not exist, [open a feature request](https://github.com/carlesonielfa/isoboard-app/issues/new?template=feature_request.yml). Describe what you are trying to do and what gets in the way today.

The problem matters more than the solution. "I paste invoices into a spreadsheet every week and have to fix the dates by hand" helps more than "add a date setting", because it shows what a good fix looks like.

You need a free GitHub account to open an issue or vote.

## How are features prioritized?

Requests with more 👍 reactions and more people describing the same need move up. Support for Windows and Linux, for example, is prioritized by demand, so vote on those issues if you want isoboard on another platform.

A request is not a promise that it will be built, but every request is read.

## How do I report a bug?

1. [Search the open issues](https://github.com/carlesonielfa/isoboard-app/issues?q=is%3Aissue%20is%3Aopen%20label%3Abug) for the same problem.
2. If you find it, add a 👍 reaction and any details that differ, such as your macOS version or the model you use.
3. Otherwise, [open a bug report](https://github.com/carlesonielfa/isoboard-app/issues/new?template=bug_report.yml) with your isoboard version, what you did, what you expected and what happened.

Check [troubleshooting](../../troubleshooting/capture-and-permissions/) first. Many capture, shortcut and provider problems have a quick fix there.

## What should I keep out of a public issue?

Issues are public. Never post:

- API keys or license keys
- Order numbers or payment details
- Screenshots or captures with private or confidential content. Use a made-up example that shows the same problem.

For purchase, license key or refund help, write to support@isoboard.app instead. Report security vulnerabilities privately through [GitHub security advisories](https://github.com/carlesonielfa/isoboard-app/security/advisories/new).

## Can I contribute code?

Yes. The source code is on [GitHub](https://github.com/carlesonielfa/isoboard-app). Start with the [developer documentation](../../developers/) and the contributing guide in the repository.
